## 1. 셀렉터 통합

`GenProviderModelSelect.tsx:25`의 `CORE_PROVIDER_OPTIONS`에 추가:

      { value: "comfy", label: "Comfy" },

모델 목록이 문제다. 다른 코어 레인은 `getImageModelOptionsForProvider`가
**생성된 정적 목록**에서 읽는다. comfy는 `/api/models`의 lane DTO에서
온다.

    /**
     * Comfy models come from the models endpoint, not the generated static
     * list, because a workflow is registered at runtime. This mirrors how the
     * MCP lanes already populate their catalogs in this same component
     * (useMcpProviders + getMcpModelCatalog), so the pattern is not new here.
     */

이 컴포넌트는 **이미** MCP 레인을 위해 런타임 카탈로그를 다룬다
(`mcpCatalog`, `modelsLoading`, `catalogError`). comfy도 같은 흐름을 탄다.

### 필수 편집 둘 — default 분기 (감사 #6)

셀렉터만 고치면 부족하다. 두 곳의 default가 comfy를 GPT로 흘려보낸다.

**(a) `ui/src/lib/imageModels.ts:89-95`**

      export function getImageModelOptionsForProvider(provider: Provider) {
        if (provider === "grok" || provider === "grok-api") return GROK_IMAGE_MODEL_OPTIONS;
        if (provider === "agy" || provider === "gemini-api") return GEMINI_IMAGE_MODEL_OPTIONS;
        if (provider === "atlascloud") return ATLASCLOUD_IMAGE_MODEL_OPTIONS;
        if (provider === "minimax") return MINIMAX_IMAGE_MODEL_OPTIONS;
        return OPENAI_IMAGE_MODEL_OPTIONS;      // <- comfy가 여기로
      }

comfy 분기를 추가해 **빈 배열**을 낸다:

      /**
       * Comfy has no static option rows: its models are workflows fetched from
       * /api/models at runtime. Returning the OpenAI list here would show
       * gpt-5.6-luna under a ComfyUI selection and send a model the lane
       * cannot execute.
       */
      if (provider === "comfy") return [];

호출부는 빈 배열일 때 런타임 카탈로그를 쓴다.

**(b) `ui/src/store/storeSettingsImpl.ts:383`** — `setProviderImpl`의 마지막
else가 provider만 바꾸고 모델을 유지한다. comfy로 전환하면 `gpt-5.6-luna`가
남아 첫 생성이 실패한다.

comfy 전환 시 **모델을 비운다**. "첫 워크플로 자동 선택"은 하지 않는다 —
등록 순서에 의미가 없어서 임의 선택이 되고, 사용자가 의도하지 않은
워크플로로 GPU를 돌리게 된다. 대신 셀렉터가 미선택 상태를 보여준다.

오프라인 워크플로는 `disabled` + 사유 표시로 남긴다. 목록에서 지우면
"내 워크플로가 사라졌다"가 되고, 그냥 두면 실패할 생성을 시작하게 된다.

## 2. 워크플로 관리자

표 하나 + 등록 폼. 목록 컬럼: 라벨 / id / origin / 상태 / 액션.

상태는 색만으로 표시하지 않는다(a11y): 점 + 텍스트("ready" / "offline").

### 등록 흐름 — 3단계

    파일 선택 (.json 또는 .png)
      -> POST /api/comfy/inspect  (저장 안 함)
      -> 바인딩 확정 화면
      -> POST /api/comfy/workflows

2단계가 이 기능의 핵심이다. `ComfyBindingConfirm`은 필드별로 후보
드롭다운을 낸다.

    /**
     * Ambiguous fields open UNSELECTED and block submit. Preselecting a guess
     * would let a user click through and end up with positive/negative
     * swapped — a failure that shows up much later as "the model ignores my
     * prompt", with nothing on screen pointing back to this dialog.
     */

각 후보에 `class_type`과 `_meta.title`을 함께 보여준다. 사용자는 자기
ComfyUI 화면에서 그 제목을 봤으므로 이게 가장 강한 단서다.

### origin 필드

`config.comfy.defaultUrl`로 미리 채우되 수정 가능하다. 여러 인스턴스를
쓰는 사람이 여기서 8189를 넣는다. 입력 즉시 도달 가능 여부를 보여준다 —
저장 후에 알게 되면 늦다.

**프로브 전에 정규화한다(감사 #7).** 사용자가 타이핑한 문자열을 그대로
fetch하지 않는다.

    /**
     * Never fetch a raw typed string. The probe goes through the server
     * (POST /api/comfy/probe), which runs normalizeComfyOrigin first — the
     * same http + loopback + explicit-port rule the store enforces. A browser
     * fetching an arbitrary typed URL is the SSRF-shaped footgun even when
     * the eventual rule is loopback-only.
     */

잘못된 URL은 프로브를 **거부**하고 형식 오류를 표시한다. 프로브 실패와
형식 오류는 다른 메시지다: 전자는 "안 켜져 있나요", 후자는 "루프백 http
주소에 포트가 필요합니다".

## 3. 동적 파라미터 폼

`ComfyParamControls`는 `McpModelPresetControls`의 구조를 따른다: 파라미터
계약(name/type/min/max/options/default)을 읽어 컨트롤을 그린다.

모델을 바꾸면 파라미터 집합이 통째로 달라진다.
`reconcileMcpPresetSelection`이 MCP에서 하는 일과 동일한 정리가 필요하다:

    /**
     * Switching workflows replaces the parameter contract wholesale. Values
     * that no longer exist in the new contract are dropped rather than carried
     * over — a stale "cfg" from another workflow would be injected into a node
     * that never declared it.
     */

## 4. i18n — 4개 전부

`tests/i18n-coverage-contract.test.ts`가 en/ko/zh-Hans/zh-Hant의 키 집합
일치를 강제한다. 하나라도 빠지면 실패다.

한국어 문구는 `cxc-kwrite` 규약을 따른다 — 번역투(~에 대해, ~를 통해)
금지, AI 관용구 금지, 일관된 어체.

예시 키:

| 키 | ko |
|---|---|
| `comfy.workflows.title` | 워크플로 |
| `comfy.workflows.empty` | 등록된 워크플로가 없습니다. ComfyUI에서 Export (API)로 뽑은 파일을 올리세요. |
| `comfy.workflows.offline` | 인스턴스가 응답하지 않습니다 |
| `comfy.bind.ambiguous` | 이 항목은 후보가 여럿이라 직접 골라야 합니다 |
| `comfy.bind.uiFormat` | UI 저장본입니다. ComfyUI에서 Export (API)로 다시 뽑아주세요 |

빈 상태 문구가 **다음 행동을 지시**한다 — 상태만 알리고 끝내지 않는다.

## 5. UX 상태 커버리지

| 상태 | 처리 |
|---|---|
| 빈 스토어 | 등록 방법을 안내하는 빈 상태 |
| 로딩 | 목록 스켈레톤 (구조를 아는 경우) |
| 헬스 프로브 중 | 행별 인라인 스피너, 표 전체는 차단하지 않음 |
| 전 인스턴스 오프라인 | 레인 disconnected + 셀렉터에서 사유 표시 |
| 일부 오프라인 | 해당 행만 offline, 나머지는 정상 사용 |
| 그래프 파싱 실패 | UI 저장본인지 여부를 구분한 에러 |
| 바인딩 미확정 | submit 비활성 + 미확정 필드 강조 |

## 6. 접근성

- 바인딩 드롭다운은 키보드로 완주 가능해야 한다(기존 `Select` 사용).
- 상태를 색만으로 인코딩하지 않는다.
- 워크플로 삭제는 확인을 받는다(되돌릴 수 없다).
- 오프라인 사유를 스크린리더가 읽도록 `aria-describedby` 연결.

   없음을 확인 (감사 #6).
7. multimode/node/agent 표면에서 comfy가 **선택지로 나타나지 않는다**
   (030 §6.5의 서버 가드와 짝을 이룬다).
