## Reader and operation implementation clarifications

- BigInt fstat/lstat identities avoid precision loss; the receipt is internal and
  is never JSON serialized. Freeze exported metadata and keep the authoritative
  candidate/roots/identity snapshot private (WeakMap keyed by returned receipt).
  Cleanup must reject an unissued/modified identity rather than trusting a caller's
  constructed object. Returning bytes never grants deletion of another path.
- Export readAgyArtifact(path, signal) and cleanupAgyArtifact(receipt). Both
  adapter imports use .js, with emitted twins generated by build:server.
- No test-only production export or request/config override. Source tests mock
  config.ts with a frozen tiny AGY_ARTIFACT_POLICY before importing the reader;
  emitted tests mock config.js using a plain-JS loader. Supply required exports
  including AGY_PROCESS_POLICY, without reading real user config. Different
  policy/graph cases use fresh isolated processes, never a cached reader with a
  mutated policy. Hosted 50MiB cases use the actual unmocked config policy.
  Exercise the public reader's real stat/read/overflow/close/cleanup paths.
- Coalesce short reads into fixed-size blocks: fill the current chunk before
  allocating the next, then use one overflow byte at the cap. Do not retain an
  entire 64KiB backing allocation for every one-byte short read. Bound chunk
  count as well as retained bytes; concatenate only after bounded EOF.
- Require absolute, non-NUL paths. On Windows reject alternate-stream colons
  beyond the drive colon before filesystem access. Canonical containment uses
  path.relative plus separator/isAbsolute checks, not string prefix resemblance.
- Missing roots are omitted, never replaced by a broader ancestor. Other root
  errors propagate as safe policy rejection. Record the original path mapping,
  canonical path, root snapshots and opened identity; revalidate before return
  and before cleanup. Root relocation during work is not new authority.
- POSIX adds O_NOFOLLOW|O_NONBLOCK; Windows uses O_RDONLY with all explicit
  lstat/realpath/fstat checks. There is no claim that Windows has POSIX no-follow
  flags, nor that portable check/open/unlink calls eliminate same-user races.
- Await each read and descriptor close; check abort between reads, after EOF
  and after close. FileHandle.read has no signal option: do not claim immediate
  cancellation of an already pending kernel read. Test holds release the actual
  read and prove settlement before restoring hooks. No abandoned I/O promise.
- An EIO remains the primary error even if cancellation occurs during later
  ref cleanup. An explicit cancellation after private receipt acquisition closes
  then attempts guarded cleanup. Policy/identity/overflow failure never grants
  cleanup. A close failure must not turn failure into success or mask a primary
  error. New policy messages omit paths/contents; preserve established I/O error
  identity rather than silently rewriting normalization in this unit.
- Cleanup uses unlink, then optional nonrecursive rmdir of the same checked
  contained parent, never an approved root. Check the parent identity/mapping
  again, and leave replacements or concurrent siblings alone. No recursive rm
  of provider-selected artifact directories. Ref staging cleanup stays unchanged.

Field chain: reader creates receipt -> only in-process operation consumes it ->
finally cleanup validates private snapshot. Serialization/deserialization N/A;
the external AgyGenerateResult fields remain unchanged. New error code creation
is the stat/stream overflow guard, mapping is providerMap INTERNAL_STATE_ERROR,
normalization retains rawCode while its existing code may be UNKNOWN. Both
direct and normalized contracts must activate; lexical exception only for policy.
