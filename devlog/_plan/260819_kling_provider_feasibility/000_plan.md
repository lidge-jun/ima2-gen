# 000 — Kling 도입 가능성 조사 (research unit)

## 목적

"kling을 넣을 수 있는지 조사한다." 구현이 아니라 **판단 근거**를 남기는
docs-only 유닛이다. 이 유닛은 프로덕션 코드를 건드리지 않는다.

답해야 하는 질문은 셋이다.

1. Kling이 지금 ima2에서 아예 안 되는 것인가, 아니면 이미 일부 되는 것인가.
2. 넣는다면 어느 레인으로 넣는가. 그 레인의 실제 코드 비용은 얼마인가.
3. 지금 당장 결정할 수 없는 것은 무엇이고, 그것을 누가 어떻게 푸는가.

## 조사 방법과 증거 등급

| 출처 | 등급 | 비고 |
|---|---|---|
| 이 저장소의 코드/스냅샷/픽스처 | **1차** | 직접 읽음. 아래 line 참조는 전부 실측 |
| 인증된 MCP tools/list 스냅샷 | **1차** | `assets/mcp-snapshots/*.sanitized.json`, 2026-07-15 캡처 |
| Kling 공식 문서 (kling.ai / klingai.com) | 2차 | grok-4.6 서브에이전트 조사, CONFIDENCE high |
| 애그리게이터 벤더 페이지 | 2차 | grok-4.6 서브에이전트 조사, CONFIDENCE medium |

서브에이전트 2대를 `xai/grok-4.6`으로 병렬 파견했다. 한 대는 공식 API,
한 대는 우회 경로를 맡았다. 두 조사 모두 저장소 접근 없이 웹만 봤고,
따라서 **로컬 코드와 충돌하는 주장은 로컬 코드를 채택했다**. 실제로
충돌이 한 건 났다 — 002 문서의 R-1 항목이다.

## 결론 요약 (먼저 읽을 것)

**Kling은 "넣을 수 있는지"의 문제가 아니다. 이미 절반은 들어와 있다.**

- Runway 레인에는 `kling-o3-pro`, `kling-3-pro`가 **이미 정적 카탈로그에
  하드코딩되어 있고**, 어댑터는 `executable: true`다.
  근거: `lib/mcp/adapters/runway.ts:51-52`, `:359`.
- Higgsfield 레인의 인증 스냅샷에는 `kling3_0`, `kling3_0_turbo`가
  존재하지만, ima2가 컴파일해 둔 `HIGGSFIELD_VIDEO_MODELS` 6종에는
  **빠져 있다**. 근거: `lib/mcp/adapters/higgsfield.ts:60-67` vs
  `assets/mcp-snapshots/higgsfield.sanitized.json`.
- 직접(1st-party) Kling API 레인은 **존재하지 않는다**. 코어 레지스트리
  8개 레인 어디에도 없다. 근거: `lib/providers/registry.ts`.

즉 선택지는 "도입하냐 마냐"가 아니라 **어느 깊이까지 도입하냐**다.
세 개의 서로 다른 비용을 가진 층이 있고, 아래로 갈수록 비싸다.

| 층 | 무엇 | 코드 비용 | 상태 |
|---|---|---|---|
| L1 | Runway MCP 경유 Kling | **0** (이미 있음) | 검증만 남음 |
| L2 | Higgsfield MCP 경유 Kling 3.0 | 소 (상수 + 픽스처) | 미검증 스냅샷 근거 |
| L3 | Kling 직접 API 레인 신설 | 대 (신규 provider) | 계약·과금 미해결 |

## work-phase 지도 (의존 순서)

이 유닛은 **조사 유닛**이므로 work-phase는 문서 산출로 끝난다.
구현은 이 유닛이 아니라, 아래 지도가 승인된 뒤 별도 유닛에서 시작한다.

| WP | decade | 내용 | 의존 |
|---|---|---|---|
| wp0 | 000 | 본 로드맵 + 결론 (docs-only) | — |
| — | 001 | 현재 코드에 Kling이 이미 어디까지 들어와 있는가 (실측) | — |
| — | 002 | 외부 경로 조사: 공식 API + 애그리게이터 | — |
| — | 003 | 세 도입안 비교와 권고 | 001, 002 |
| — | 090 | 조사 결론 / 미해결 / 다음 결정권자 | 001-003 |

## 이 유닛의 범위 (IN)

- 코드 실측 기반의 현재 상태 기술
- 외부 경로의 계약(엔드포인트/인증/모델 id/과금) 정리
- 도입안별 변경 지점 목록과 리스크

## 범위 밖 (OUT — 금지)

- 프로덕션 코드 변경. 어댑터/레지스트리/라우트/UI 어느 것도 건드리지 않는다.
- 유료 API 키 발급, 결제, 라이브 과금 호출. 예산 승인 사안이다
  (선례: #152 canary가 예산 미승인으로 멈춰 있음).
- 릴리스, 이슈 생성, 푸시.

## 검증 게이트

docs-only이므로 코드 게이트는 해당 없다. 대신 이 유닛의 수용 기준은:

1. 001의 모든 주장이 `파일:line`으로 추적 가능할 것.
2. 002의 모든 외부 사실이 출처 URL을 가지거나 UNVERIFIED로 표시될 것.
3. 003이 세 안 각각의 **변경 파일 목록**을 명시할 것 (추정 금지, 실제 경로).
4. 090이 "지금 결정 못 하는 것"을 사람에게 넘길 것.
